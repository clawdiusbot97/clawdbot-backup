## 3) Flujo paso a paso: Cotización de Auto

### Paso 0: Cliente escribe por WhatsApp
> *"Hola, quiero cotizar un Gol 2021"*

### Paso 1: Ingestion Service
- Recibe webhook de WhatsApp
- Crea/actualiza `Conversation`
- Guarda `Message` (actor: customer)
- Publica evento: `message.received`

### Paso 2: Decision Engine (IA + Reglas)
**A) Classifier Agent** (rápido, barato)
- Input: texto del mensaje
- Output: `intent = "cotizacion_auto"`, confidence = 0.94

**B) Extraction Agent** (evidence-bound)
- Input: texto + historial de conversación
- Output:
  - `vehicle.marca = "Volkswagen"` (extraído, confianza 0.95)
  - `vehicle.modelo = "Gol"` (extraído, confianza 0.98)
  - `vehicle.anio = 2021` (extraído, confianza 0.99)
  - `missing_fields = ["cilindrada", "uso", "zona", "edad_conductor"]`

**C) Crear DecisionObject**
```json
{
  "type": "CotizacionAuto",
  "status": "needs_info",
  "data": { "vehicle": { "marca": "Volkswagen", "modelo": "Gol", "anio": 2021 } },
  "missing_fields": ["cilindrada", "uso", "zona", "edad_conductor"]
}
```

**D) Emitir eventos**
- `decision.detected` (cotización_auto)
- `decision.needs_info` (faltan datos)

### Paso 3: Process Execution Layer

El motor arranca el template `cotizacion_auto_v1`:

```yaml
template: cotizacion_auto_v1
steps:
  1. recopilar_datos:
     - mientras haya missing_fields
     - preguntar al cliente (IA o humano)
     - esperar respuesta
     - actualizar DecisionObject
  
  2. validar_completitud:
     - si faltan campos críticos → volver a paso 1
     - si está completo → continuar
  
  3. ejecutar_cotizacion:
     - llamar APIs de aseguradoras (o enviar emails)
     - recibir tablas de precios
     - generar comparativo
     - guardar resultado en DecisionObject
  
  4. presentar_al_cliente:
     - generar PDF/mensaje con recomendación
     - enviar por WhatsApp
     - esperar respuesta (aceptar/rechazar/modificar)
  
  5. validar_aceptacion:
     - si cliente acepta → continuar
     - si rechaza → fin del proceso (o nueva cotización)
  
  6. gate_aprobacion_humana:  # <-- GATE DE SEGURIDAD
     - tipo: "human_approval_required"
     - razón: "emision_poliza_requiere_corredor"
     - notificar a corredor: "Cliente aceptó cotización X. ¿Emitir póliza?"
  
  7. emitir_poliza:  # solo si corredor aprueba
     - ejecutar emisión en aseguradora
     - generar documentación
     - notificar cliente
```

### Paso 4: Modo de operación (control_mode)

**Si `control_mode = ai_first`:**
- Paso 1-4: IA conversa directamente con cliente pidiendo datos faltantes
- Paso 5: IA envía cotización al cliente
- Paso 6: Se detiene, notifica corredor, espera aprobación humana

**Si `control_mode = human_led`:**
- Todo el paso 1-4: IA extrae datos en background pero **no habla**
- En el CRM se ve el "Workbench" con: intent detectado, datos faltantes, sugerencias
- Corredor escribe manualmente (o copia sugerencias de IA)
- Paso 6: Corredor decide ejecutar o no

## 4) Gate de Aprobación Humana (lo crítico)

En `step_6` (y cualquier paso "material"), el sistema:

1. **Cambia estado del ProcessExecution** a `waiting_human_approval`
2. **Crea ApprovalRequest**:
```json
{
  "id": "apr_001",
  "process_id": "proc_001",
  "decision_id": "dec_001",
  "type": "emitir_poliza",
  "context": {
    "cliente": "Juan Pérez",
    "vehiculo": "Gol 2021",
    "cotizacion_seleccionada": "SURA - $45.000/anual",
    "premio": "$45.000"
  },
  "requested_at": "2026-03-13T10:00:00Z",
  "expires_at": "2026-03-13T18:00:00Z"  // SLA
}
```

3. **Notifica al corredor**:
   - Dashboard: badge rojo "Aprobación pendiente"
   - Email/WhatsApp: "Tienes una cotización esperando aprobación"
   - En la conversación: indicador visual

4. **Corredor acciona**:
   - Botón "✅ Aprobar y Emitir" → continúa a paso 7
   - Botón "✏️ Modificar" → vuelve a paso 4
   - Botón "❌ Rechazar" → cierra proceso

5. **Audit trail**:
   - Quién aprobó, cuándo, con qué contexto
   - Todo queda en `DecisionEvent` (append-only)

## 6) Ejemplo de código (pseudocódigo del Process Engine)

```ruby
class CotizacionAutoProcess < BaseProcess
  step :recopilar_datos do
    on_entry do
      while decision.missing_fields.any?
        question = generate_question(decision.missing_fields.first)
        send_whatsapp(decision.conversation, question)
        wait_for_response
      end
    end
  end

  step :ejecutar_cotizacion do
    on_entry do
      cotizaciones = []
      Aseguradora.all.each do |aseg|
        cotizaciones << aseg.api.cotizar(decision.data)
      end
      decision.update!(
        cotizaciones: cotizaciones,
        recomendacion: select_best(cotizaciones)
      )
    end
  end

  step :presentar_al_cliente do
    on_entry do
      pdf = generate_pdf(decision.cotizaciones, decision.recomendacion)
      send_whatsapp(decision.conversation, pdf, "¿Te interesa esta opción?")
      wait_for_response
    end
    
    on_response do |msg|
      if msg.text =~ /si|ok|acepto/
        transition_to :gate_aprobacion_humana
      else
        transition_to :fin_rechazado
      end
    end
  end

  step :gate_aprobacion_humana do
    on_entry do
      create_approval_request!(
        type: :emitir_poliza,
        notify: decision.broker,
        expires_in: 8.hours
      )
      # Process queda en "waiting" hasta que alguien llame approve()
    end
  end

  step :emitir_poliza, requires_approval: true do
    on_entry do
      poliza = decision.recomendacion.aseguradora.emitir!(decision.data)
      decision.update!(status: :executed, poliza_id: poliza.id)
      notify_client("¡Tu póliza está emitida! Número: #{poliza.number}")
    end
  end
end
```
