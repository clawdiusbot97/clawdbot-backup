# Thesis Intel — 2026-05-24

## TL;DR
- Content provenance is converging on layered signals (C2PA metadata + watermarking + public verification), which will become table-stakes for document, image, and voice workflows.
- Voice AI is scaling into enterprise (large ARR, on-prem/local deployment narratives), making governance (consent, audit logs, anti-fraud) a near-term differentiator.
- Infra is shifting toward hybrid/on-prem “agentic” deployments, so Brokia should design for deployability and cost controls from day one.

## Hallazgos
1) OpenAI strengthens content provenance with C2PA conformance + SynthID watermarking + a public verification tool
   - Why it matters: Insurance and broker workflows will increasingly require verifiable media origin (customer-submitted docs/images, claim evidence) to reduce fraud and comply with audits.
   - Links: https://openai.com/index/advancing-content-provenance/
   - Idea para Brokia: Add “provenance checks” as a pipeline step (store C2PA metadata when present, run watermark/provenance detectors when available, and log a verification verdict + confidence).

2) OpenAI + Dell partnership for hybrid/on-prem Codex deployments (enterprise direction signal)
   - Why it matters: Buyers want AI agents where data lives (VPC/on-prem). This will bleed into insurtech procurement.
   - Links: https://openai.com/news/ (see “OpenAI and Dell Technologies partner…”, May 18, 2026)
   - Idea para Brokia: Make Brokia’s core agent runtime “deployment-agnostic” (SaaS-first, but with a documented path to VPC/on-prem, plus caching/batching switches).

3) OpenAI response to TanStack npm supply-chain attack (agent/tooling security reminder)
   - Why it matters: Agentic products increase dependency surface (packages, plugins, connectors). Supply-chain controls become part of product trust.
   - Links: https://openai.com/news/ (see “Our response to the TanStack npm supply chain attack”, May 13, 2026)
   - Idea para Brokia: Ship a “connector allowlist + integrity checks” posture (pinned versions, SBOM, basic policy engine for tool calls, and audit trails).

4) ElevenLabs crosses $500M ARR and emphasizes enterprise expansion
   - Why it matters: Voice is no longer experimental, it is enterprise-scale, so expect rapid commoditization plus tighter compliance asks.
   - Links: https://elevenlabs.io/blog/blog/500m-arr-and-new-investors
   - Idea para Brokia: Prototype a broker voice agent for lead qualification and renewal follow-ups, but add consent capture + call recording redaction + model output logging.

5) “Enterprise voice AI, deployed locally” positioning (on-prem voice narrative)
   - Why it matters: Regulated orgs will demand local processing for voice and PII (latency + residency).
   - Links: https://elevenlabs.io/blog (see “Enterprise voice AI, deployed locally”, Apr 9, 2026)
   - Idea para Brokia: Offer a “local mode” architecture for voice and document parsing (edge transcription/extraction, centralized policy + audit).

6) ClickHouse open-sources Silk (fiber scheduler + io_uring integration) as a high-concurrency infra building block
   - Why it matters: High-throughput agent systems (voice, streaming extraction, multi-tenant RAG) benefit from predictable concurrency primitives.
   - Links: https://github.com/ClickHouse/silk
   - Idea para Brokia: If building performance-critical components (streaming pipelines, high fan-out tasks), evaluate fiber-based runtimes or async designs with explicit backpressure.

## Ideas accionables para Brokia
- Add a “Provenance & Trust” module to the ingestion pipeline (credentials, watermark checks, fraud flags, immutable audit log).
- Design a deployment story early (SaaS now, VPC/on-prem later) by separating data plane (customer data) from control plane (policies, prompts, audit).
- Ship security defaults for agent tooling (connector allowlist, signed artifacts, version pinning, human-in-the-loop for sensitive actions).
