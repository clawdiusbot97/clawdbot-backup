# Thesis Intel — 2026-05-25

## TL;DR
- Coding agents are converging on “terminal-native” workflows with aggressive caching/latency optimization, pushing price-performance down and raising user expectations for always-on copilots.
- Tooling surfaces are becoming programmable in unexpected places (e.g., Jira), which is a reminder that governance and auditability need to assume “any system can become a compute substrate”.
- High-concurrency infra primitives (time sync, schedulers, backpressure) remain an under-priced advantage for voice + doc pipelines, where tail latency and ordering matter.

## Hallazgos
1) DeepSeek Reasonix: terminal-native coding agent with high caching/low cost positioning
   - Why it matters: The cost curve for agentic coding workflows keeps dropping, which accelerates “agents everywhere” expectations (including internal tools for brokers/ops).
   - Links: https://esengine.github.io/DeepSeek-Reasonix/ | https://news.ycombinator.com/item?id=48256953
   - Idea para Brokia: Diseñar el runtime de agentes con caching/batching desde el día 1 (cache de embeddings, memoización de tool calls, y presupuesto por workflow) para evitar sorpresas de costo.

2) Jira is Turing-Complete (programmability emerging in workflow tools)
   - Why it matters: If everyday enterprise tooling can become executable/programmable, then security and audit logging must assume non-obvious execution paths and data flows.
   - Links: https://seriot.ch/computation/jira.html | https://news.ycombinator.com/item?id=48263253
   - Idea para Brokia: Implementar un “policy engine” simple para tool calls (allowlist + redaction + audit trail) y tratar integraciones como superficie de ataque.

3) White Rabbit: sub-nanosecond synchronization for distributed systems
   - Why it matters: Voice + streaming document extraction benefit from precise timing (alignment, ordering, replay), especially in multi-node deployments.
   - Links: https://ohwr.org/projects/white-rabbit/ | https://news.ycombinator.com/item?id=48245916
   - Idea para Brokia: Para pipelines en tiempo real (voz o ingestión masiva), instrumentar end-to-end timing (timestamps, jitter, tail latency) y preparar replay determinístico.

4) Mozilla workaround for Intel Raptor Lake crash (platform reliability risk)
   - Why it matters: When customer environments vary (endpoints, VDI, mixed CPUs), reliability issues can look like “AI bug” but are actually platform-level.
   - Links: https://phabricator.services.mozilla.com/D301917 | https://news.ycombinator.com/item?id=48242546
   - Idea para Brokia: Añadir telemetría mínima (CPU/OS/runtime) + “safe mode” toggles para degradar features (streaming, SIMD, codecs) y reducir incident response time.

5) Migrating from Go to Rust (correctness vs ergonomics and incremental migration)
   - Why it matters: Teams are increasingly willing to pay migration cost for correctness guarantees and runtime control in critical services.
   - Links: https://corrode.dev/learn/migration-guides/go-to-rust/
   - Idea para Brokia: Si un componente se vuelve safety-critical (PII redaction, policy enforcement, signature verification), considerar implementarlo como servicio aislado con contratos estrictos.

6) Web-based multitrack audio editing (open-source) as a capability building block
   - Why it matters: Lightweight in-browser audio tooling can support review/QA workflows (call snippets, training data triage) without heavy desktop dependencies.
   - Links: https://audiomass.co/?multitrack=1 | https://news.ycombinator.com/item?id=48258015
   - Idea para Brokia: Explorar un “call review UI” para voice agents (recortes, anotaciones, PII redaction preview) como herramienta interna primero.

## Ideas accionables para Brokia
- Definir un “cost control checklist” para cada workflow (caching, batch, truncation, fallbacks) y medir costo por tarea desde el inicio.
- Tratamiento de integraciones como software supply-chain: allowlist, scopes mínimos, auditoría, y pruebas de abuso.
- Priorizar instrumentación de latencia y trazabilidad (timestamps, correlación) en voz y extracción de documentos para debugging y cumplimiento.
