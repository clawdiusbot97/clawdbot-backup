# Thesis Intel — 2026-04-28

## TL;DR (3 bullets)
- Document AI is converging on “eval-first” extraction pipelines (schema + validation + human-in-the-loop) as the practical moat.
- Voice AI risk is shifting from cloning quality to governance (consent, watermarking, call-center abuse detection) and latency.
- Insurtech winners are packaging automation as workflow (claims + underwriting + renewals) with strong auditability.

## Hallazgos (6–10)
1) **Structured document extraction is becoming eval-driven (golden sets + error taxonomies)**
   - Why it matters: enables measurable improvements, reduces hallucinations in policy/claims intake.
   - Links: https://arxiv.org/search/?query=document+information+extraction&searchtype=all
   - Idea for Brokia: build an “Extraction QA” module (field-level confidence, validator rules, reviewer queue).

2) **RAG over long PDFs is shifting toward chunk-free / layout-aware retrieval**
   - Why it matters: insurance docs depend on tables, headers, and cross-references.
   - Links: https://arxiv.org/search/?query=layout+aware+retrieval&searchtype=all
   - Idea for Brokia: add layout-aware ingestion (table structure + section anchors) before vectorization.

3) **Voice agents: real-time latency is now a product differentiator (end-to-end <500ms)**
   - Why it matters: broker calls and WhatsApp voice interactions degrade fast over 1s latency.
   - Links: https://arxiv.org/search/?query=streaming+speech+to+speech&searchtype=all
   - Idea for Brokia: benchmark a “low-latency voice loop” and set an internal SLO (p95) for deployments.

4) **Anti-fraud is blending doc + voice signals (cross-modal anomaly detection)**
   - Why it matters: claims fraud often mixes forged PDFs, synthetic voice, and inconsistent narratives.
   - Links: https://arxiv.org/search/?query=multimodal+fraud+detection&searchtype=all
   - Idea for Brokia: pilot a cross-modal risk score on intake (doc consistency + call transcript cues).

5) **Compliance pressure: audit logs and data residency are moving from ‘enterprise nice-to-have’ to ‘table stakes’**
   - Why it matters: insurers require traceability (who saw what, which model, which prompt, which data).
   - Links: https://www.iso.org/standard/81230.html
   - Idea for Brokia: ship immutable audit trails (request id, model id, input hashes, outputs, reviewer actions).

6) **Cost control: caching/batching and routing to smaller models is becoming standard practice**
   - Why it matters: brokerage workflows are repetitive; savings compound quickly.
   - Links: https://platform.openai.com/docs/guides/latency-optimization
   - Idea for Brokia: add a routing layer (cheap model for classification, strong model for edge cases).

## Ideas accionables para Brokia (3–5)
- Build a policy/claim “golden set” (50–200 docs) + eval harness; track field-level F1 and rejection reasons.
- Add a validation DSL for extracted fields (dates, sums, coverage limits) to reduce manual rework.
- Implement audit logging + export (JSONL) as a first-class feature for insurer compliance.
- Prototype a voice intake assistant with explicit consent + risk flags (deepfake suspicion, unusual cadence).
