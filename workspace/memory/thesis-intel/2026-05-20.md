# Thesis Intel — 2026-05-20

## TL;DR (3 bullets)
- Los “frontier model refreshes” siguen bajando costo/latencia (Gemini 3.5 Flash), esto cambia el baseline económico para copilotos de brokers.
- La provenance/verificación de contenido se está volviendo default (OpenAI adopta SynthID), clave para defensa anti-fraude en imágenes/documentos.
- Señales claras de que seguridad y guardrails pasan a ser producto (incident reports, repos access, guardrails frameworks).

## Hallazgos (6)
1) Gemini 3.5 Flash
- Por qué importa para la tesis: modelos más rápidos/baratos habilitan workflows de extracción y clasificación a escala (Document AI, triage de emails/WhatsApp) sin romper budget.
- Links:
  - https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-5/
- Idea accionable (Brokia): diseñar un “pipeline 2-tiers”: Flash/cheap model para extracción + reglas deterministas; escalar a modelo grande solo cuando confidence < umbral.

2) OpenAI adopta SynthID para watermark de imágenes + verificación
- Por qué importa para la tesis: provenance verificable reduce riesgo de fraude con adjuntos (claims/evidence) y ayuda a compliance (auditoría, disputas).
- Links:
  - https://openai.com/index/advancing-content-provenance/
- Idea accionable (Brokia): agregar un “attachment provenance step” en siniestros: detectar watermark/provenance cuando exista, y registrar hash + metadata en audit log.

3) Mistral AI adquiere Emmi AI
- Por qué importa para la tesis: consolidación en providers europeos refuerza la opción “sovereign/region-first” para despliegues con data residency.
- Links:
  - https://www.emmi.ai/news/mistral-ai-acquires-emmi-ai
- Idea accionable (Brokia): preparar una “matriz de residencia de datos” por cliente (UY/AR/UE/US) y una capa de routing por región/proveedor.

4) Infomaniak migra a un foundation model para proteger privacidad
- Por qué importa para la tesis: proveedores cloud están posicionando “privacy-first AI” como diferenciador, señal para enterprise adoption.
- Links:
  - https://news.infomaniak.com/en/infomaniak-foundation-sovereign-cloud/
- Idea accionable (Brokia): empaquetar “modo regulado”: egress allowlist, no-retention, cifrado de adjuntos, y logs de acceso por herramienta.

5) Show HN: Forge (guardrails) mejora un 8B del 53% al 99% en tareas agentic
- Por qué importa para la tesis: guardrails + evaluación se vuelven palanca principal para confiabilidad en agentes (docs/voz) sin depender solo del modelo.
- Links:
  - https://github.com/antoinezambelli/forge
- Idea accionable (Brokia): crear un “policy checker” determinista para salidas críticas (cobertura/exclusiones/required-docs) y medir tasa de corrección con y sin guardrails.

6) GitHub investiga acceso no autorizado a repos internos
- Por qué importa para la tesis: refuerza threat-model de supply chain y exposición de credenciales, especialmente en CI y tooling de agentes.
- Links:
  - https://twitter.com/github/status/2056884788179726685
- Idea accionable (Brokia): hardening baseline: secrets scanning, rotación de tokens, 최소 permisos en CI, y auditoría de accesos a repos/artefactos.

## Ideas accionables para Brokia (4)
- Implementar pipeline cheap→expensive con métricas (costo/latencia/faithfulness) para extracción de pólizas.
- Añadir verificación/provenance de adjuntos (hash + metadata + detección de watermark cuando aplique).
- Definir “modo regulado” como feature vendible (logs, retención, egress, cifrado).
- Montar harness de evaluación + guardrails para tareas críticas (coverage decisions, required docs, fraud flags).
