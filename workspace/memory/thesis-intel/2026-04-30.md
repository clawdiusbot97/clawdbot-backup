# Thesis Intel — 2026-04-30
## TL;DR (3 bullets)
- Voz en tiempo real: la latencia de RAG se está atacando con “prefetch + cache semántico” para agentes de voz.
- STT/ASR streaming optimizado (cache-aware) empieza a volverse un bloque “commodity” para voice agents a gran escala.
- En documentos, el foco se mueve a parsing de elementos visuales (figuras/tablas/captions) para RAG multimodal confiable.

## Hallazgos (6–10)
1) VoiceAgentRAG: prefetch de RAG para bajar latencia en voice agents
   - Por qué importa: en brokers/call-centers, una respuesta tardía mata la experiencia; separar retrieval en un agente “slow thinker” permite TTFB bajo sin perder grounding.
   - Links: https://arxiv.org/abs/2603.02206
   - Idea Brokia: prototipar “retrieval prefetcher” que, durante la conversación, anticipe próximos intents (renovación, coberturas, exclusiones) y caliente cache de snippets de pólizas.

2) Nemotron Speech ASR (cache-aware streaming) como base para voz a baja latencia
   - Por qué importa: para WhatsApp/llamadas, el ASR streaming con cache reduce costo y mejora latencia sin depender de GPUs enormes.
   - Links: https://huggingface.co/blog/nvidia/nemotron-speech-asr-scaling-voice-agents
   - Idea Brokia: definir un “latency budget” por pipeline (VAD+ASR+LLM+TTS) y testear ASR streaming como opción default para llamadas.

3) Parsing production-ready de elementos visuales en PDFs (figuras/tablas/forms) 
   - Por qué importa: en seguros, muchas pólizas y anexos incluyen tablas/figuras, si se extraen mal, el RAG alucina o pierde cláusulas críticas.
   - Links: https://ui.adsabs.harvard.edu/abs/2026arXiv260423276L/abstract
   - Idea Brokia: agregar un “visual elements extractor” (tablas/figuras + captions) y guardar esos artefactos como nodos con trazabilidad en el índice.

4) DTBench: benchmark sintético para Document-to-Table extraction
   - Por qué importa: para cotización y underwriting, extraer tablas (límites, deducibles, riders) es clave, y hace falta evaluar con taxonomía clara.
   - Links: https://www.semanticscholar.org/paper/DTBench%3A-A-Synthetic-Benchmark-for-Extraction-Guo-Du/bfe1bf434ef2c732d1a434ae38109415718e44fa
   - Idea Brokia: crear un “mini-DTBench” interno con tablas reales de pólizas locales y medir precisión por campo (límites, exclusiones, vigencia).

5) Señal enterprise: “agentic AI” aplicado a workflows core de insurance (Microsoft)
   - Por qué importa: el discurso se consolida en torno a agentes que orquestan tareas (claims/underwriting) con guardrails, no solo copilots de chat.
   - Links: https://www.microsoft.com/en-us/microsoft-cloud/blog/financial-services/2026/02/18/from-bottlenecks-to-breakthroughs-how-agentic-ai-is-reshaping-insurance/
   - Idea Brokia: enmarcar Brokia como “workflow agent” (quote → doc collection → extraction → summary → human approval) con auditoría por paso.

6) World Insurance Report 2026 (Capgemini) como termómetro de adopción de AI en insurers
   - Por qué importa: ayuda a priorizar: customer service, underwriting y claims aparecen como use cases top, útil para narrativa y roadmap.
   - Links: https://www.capgemini.com/wp-content/uploads/2025/11/WCR_2026_Final-2MB-version.pdf
   - Idea Brokia: mapear features a esos 3 use cases y definir 1 KPI por etapa (tiempo de cotización, STP rate, fraude detectado).

## Ideas accionables para Brokia (3–5)
- Diseñar “prefetch RAG” para voz: anticipación de intents + cache semántico, con métricas de TTFB y groundedness.
- Implementar un harness de evaluación doc→tabla (campos críticos) y bloquear deploys si baja precisión.
- Incorporar extracción de elementos visuales (tablas/figuras+citation) para mejorar RAG en PDFs complejos.
- Documentar el pipeline como “agentic workflow” con audit log por paso (compliance + debugging).
