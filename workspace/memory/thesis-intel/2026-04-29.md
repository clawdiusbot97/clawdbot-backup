# Thesis Intel — 2026-04-29

## TL;DR (3 bullets)
- Voice + compliance is converging on real-time redaction, retention policy automation, and auditable control planes.
- “Secure RAG” is becoming an architecture discipline (ingestion filtering, access control, audit trails), not just a prompt pattern.
- Claims/document automation content is still vendor-heavy, but the actionable angle is building measurable extraction quality + exception workflows.

## Hallazgos (6–10)
1) Securing the RAG ingestion pipeline (AWS Security Blog)
   - Why it matters: ingestion is the highest-risk surface for prompt injection, sensitive-data leakage, and downstream hallucination anchoring.
   - Links: https://aws.amazon.com/blogs/security/securing-the-rag-ingestion-pipeline-filtering-mechanisms/
   - Actionable idea for Brokia: implement an “ingestion firewall” (MIME allowlist, file-type validators, URL/domain allowlist, PII scan, and content policy filters) with an auditable decision log per document.

2) Governance patterns for RAG systems (Data governance in RAG systems)
   - Why it matters: brokers/insurers will demand demonstrable controls (lineage, retention, and access) for any AI touching customer data.
   - Links: https://artemmukhopad.substack.com/p/data-governance-in-rag-systems-security
   - Actionable idea for Brokia: ship a governance dashboard: per-tenant data sources, retention timers, RBAC mappings, and “who asked what” query logs.

3) Confidential / auditable RAG framing for insurance audit use cases (OPAQUE)
   - Why it matters: “auditability” is a strong differentiator when selling into regulated workflows (claims, underwriting, compliance).
   - Links: https://www.opaque.co/resources/articles/confidential-rag-for-insurance-auditing
   - Actionable idea for Brokia: create an “audit packet” export (inputs, retrieved chunks hashes, model version, output, reviewer actions) for each AI-assisted decision.

4) Real-time call redaction as a product wedge for Voice AI in insurance/compliance (MosaicVoice)
   - Why it matters: voice agents and call analytics are gated by PCI/PHI/PII controls, especially for outsourcing/call-center environments.
   - Links: https://www.mosaicvoice.ai/blog/how-real-time-call-redaction-works-removing-pci-phi-without-breaking-conversation-flow
   - Actionable idea for Brokia: build a modular “redaction middleware” that sits between ASR and downstream LLMs, emitting both redacted transcript and a sealed vault of originals with strict access.

5) Compliance positioning for contact centers (Observe.AI solution page)
   - Why it matters: buyers increasingly evaluate vendors by compliance capabilities (script guidance, redaction, audit trails) more than model quality.
   - Links: https://www.observe.ai/solutions/contact-center-compliance
   - Actionable idea for Brokia: productize compliance primitives: consent capture, DNC/TCPA checks, policy-based retention, and configurable “restricted topics” guardrails.

6) Pragmatic claims automation framing (Nurix claims automation explainer)
   - Why it matters: there is appetite for end-to-end orchestration (intake → extraction → routing → decisions) as long as exceptions and human-in-the-loop are first-class.
   - Links: https://www.nurix.ai/blogs/claims-automation-transforming-insurance-industry
   - Actionable idea for Brokia: define a benchmark suite for broker/claims docs (policy PDFs, endorsements, invoices) with extraction quality metrics and an exception queue UX.

## Ideas accionables para Brokia (3–5)
- Add “Evidence Mode” to every AI output: show retrieved sources (chunk ids), confidence cues, and a 1-click reviewer sign-off (audit logged).
- Build a Voice Compliance Pack: real-time redaction + retention policies + downloadable audit trail for each call.
- Implement a tenant-level data residency switch (storage region + encryption keys) and surface it in sales-ready compliance docs.
- Launch an internal evaluation harness for document extraction (tables, scans, mixed layouts) with weekly regression reports.
