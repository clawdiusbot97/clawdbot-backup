# Thesis Intel — 2026-05-07

## TL;DR
- Document AI is shifting from “OCR + rules” to benchmarked multimodal literacy and multi-doc analytical QA, which makes evaluation a first-class product surface.
- Streaming voice stacks are converging on block-wise generation and codec-aware decoding for ultra-low latency, enabling more natural WhatsApp style agents.
- Insurance automation work is increasingly framed as end-to-end pipelines (VLM + structured extraction + workflow), not single-model demos.

## Hallazgos
1) CC-OCR V2: Benchmarking LMMs for real-world document processing
   - Why it matters: pushes doc literacy evaluation closer to production settings, useful for choosing VLMs for policy/claim PDFs.
   - Links: https://arxiv.org/search/?query=document+information+extraction+evaluation&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: build a Brokia internal “policy literacy” eval set aligned to CC-OCR style tasks (tables, forms, noisy scans), track regression per model.

2) MuDABench: multi-document analytical QA over semi-structured corpora
   - Why it matters: matches the real shape of underwriting (multiple docs, contradictions), and tests RAG beyond single-doc retrieval.
   - Links: https://arxiv.org/search/?query=document+information+extraction+evaluation&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: implement a multi-doc QA mode where answers must cite doc spans and resolve conflicts, then score on “consistency + citation coverage”.

3) KYC-style multistage extraction for long scanned financial documents
   - Why it matters: similar constraints to insurance submissions (long PDFs, variable layouts), suggests pipeline wins over monolithic prompts.
   - Links: https://arxiv.org/search/?query=document+information+extraction+evaluation&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: ship a 3-stage extraction: layout chunking → field candidates → verifier model, with per-field confidence and human review queue.

4) Ultra-low latency streaming TTS via block-wise generation + depth-wise codec decoding
   - Why it matters: lowers perceived latency for conversational agents, making voice broker assistants usable in live calls.
   - Links: https://arxiv.org/search/?query=low+latency+text+to+speech+streaming&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: define a “time-to-first-phoneme” KPI and choose TTS stack accordingly (streaming first token <300ms target).

5) CTC-TTS: dual-streaming TTS with CTC alignment
   - Why it matters: alignment-driven streaming can stabilize prosody while keeping latency low (good for compliance disclaimers).
   - Links: https://arxiv.org/search/?query=low+latency+text+to+speech+streaming&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: add a “compliance preamble” streaming path that prioritizes clarity over style, then switch to expressive voice.

6) Claim Automation using Large Language Model (insurance)
   - Why it matters: signals growing body of work treating claims as workflow automation, useful for positioning Brokia beyond quoting.
   - Links: https://arxiv.org/search/?query=insurance+claims+automation+language+model&searchtype=all&abstracts=show&order=-announced_date_first&size=50
   - Idea: prototype a claims intake agent: triage → missing info checklist → structured claim packet → handoff to adjuster.

## Ideas accionables para Brokia
- Create a small, private “policy/claim doc eval suite” (tables + scans + handwritten artifacts) and run weekly model bake-offs.
- Build a multi-doc contradiction resolver for underwriting submissions (explicit conflict detection + citations).
- Add streaming voice KPIs (TTFF, barge-in, interruption recovery) as first-class metrics for any WhatsApp/phone agent.
