# Thesis Intel — 2026-05-19

## TL;DR (3 bullets)
- La “conectividad de agentes” se está formalizando en tooling (SDKs + MCP servers), bajando fricción para integrar agentes con sistemas reales.
- Ataques de supply chain en npm escalan y empiezan a apuntar explícitamente a entornos de CI y tooling de agentes, esto empuja hardening como feature base.
- El stack de copilotos de desarrollo sigue subiendo el estándar de confiabilidad en tareas largas, una señal para diseñar agentes con mejor seguimiento de planes y verificación.

## Hallazgos (6)
1) Anthropic adquiere Stainless (SDKs + MCP server tooling)
- Por qué importa para la tesis: refuerza que la ventaja competitiva en agentes no es solo el modelo, sino el “plumbing” (specs, SDKs, conectores) que habilita integración segura y mantenible.
- Links:
  - https://www.anthropic.com/news/anthropic-acquires-stainless
- Idea accionable (Brokia): diseñar un “conector kit” para carriers y brokers: API spec (OpenAPI) + generación de SDK + MCP server interno con permisos finos y auditoría.

2) Ataque masivo a npm: 300+ paquetes comprometidos en minutos (SafeDep)
- Por qué importa para la tesis: el riesgo de supply-chain impacta directo en productos de Document AI/Voice AI si dependencias o pipelines de CI exfiltran secretos (PII, credenciales, llaves).
- Links:
  - https://safedep.io/mini-shai-hulud-strikes-again-314-npm-packages-compromised/
- Idea accionable (Brokia): baseline de seguridad: lockfiles estrictos, allowlist de dependencias, CI con permisos mínimos, rotación de tokens, y “quarantine builds” para cambios en deps.

3) Cursor lanza Composer 2.5 (mejor comportamiento en tareas largas)
- Por qué importa para la tesis: la UX de “agente que trabaja” está mejorando, lo que eleva expectativas de usuarios B2B sobre continuidad, explicación y control en workflows largos.
- Links:
  - https://cursor.com/blog/composer-2-5
- Idea accionable (Brokia): en flujos de siniestros/renovaciones, usar checkpoints visibles: plan → evidencia → borrador → confirmación, con validaciones automáticas antes de enviar al carrier.

4) Recap de 6 meses de LLMs y el “inflection point” de noviembre 2025 (Simon Willison)
- Por qué importa para la tesis: sirve como mapa de tendencias para decidir dónde invertir: evaluación, coding, herramientas, y límites de benchmarks.
- Links:
  - https://simonwillison.net/2026/May/19/5-minute-llms/
- Idea accionable (Brokia): mantener un “model change log” mensual (costo/latencia/calidad) y una suite pequeña de evals sobre documentos de pólizas y conversaciones de broker.

5) Litigio Musk vs OpenAI: veredicto unánime contra Musk por plazos (TechCrunch)
- Por qué importa para la tesis: baja incertidumbre legal para un actor central del mercado y afecta narrativa de gobernanza, lo cual suele anticipar cambios en compliance y producto.
- Links:
  - https://techcrunch.com/2026/05/18/elon-musk-has-lost-his-lawsuit-against-sam-altman-and-openai/
- Idea accionable (Brokia): mantener “compliance posture” agnóstico a proveedor: logs, auditoría, retención, export, y data residency como capas propias.

6) Señal para insurtech: seguridad operacional como diferenciador (derivado del ataque npm)
- Por qué importa para la tesis: en seguros, confianza y trazabilidad son producto. El stack de automatización (docs/voz) debe venir con controles por defecto.
- Links:
  - https://safedep.io/mini-shai-hulud-strikes-again-314-npm-packages-compromised/
- Idea accionable (Brokia): “modo regulado” por conversación: retención explícita, redacción de PII, y evidencia (hash de adjuntos/audio + timestamps) para auditoría.

## Ideas accionables para Brokia (4)
- Implementar un conector tipo MCP para 1 carrier objetivo, con permisos mínimos y logs completos.
- Agregar política de dependencias (SLSA-lite): pinning, verificación de integridad, escaneo de secretos en CI.
- Diseñar harness de agentes con checkpoints visibles y verificación (antes de enviar emails/documentos).
- Crear mini-suite de evals: extracción de pólizas (PDF) + QA con citas + detección de alucinaciones.
