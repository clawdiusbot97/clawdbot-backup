# Thesis Intel — 2026-05-29
## TL;DR (3 bullets)
- Docling and Unstructured remain strong baselines for local-first document ETL into RAG, including tables/layout and structured exports.
- Voice stacks are converging on “single API” or tightly integrated STT+TTS+orchestration, which is useful for broker/claims call triage.
- OWASP’s GenAI/LLM Top 10 is a handy daily checklist for threat modeling (prompt injection, data leakage) before shipping broker copilots.

## Hallazgos (6–10)
1) Docling (IBM/Docling project) as a unified document representation + export layer
   - Why it matters: a consistent intermediate format (DoclingDocument) reduces downstream brittleness across PDFs, DOCX, PPTX, XLSX, HTML and scanned docs.
   - Links: https://github.com/docling-project/docling , https://docling-project.github.io/docling/
   - Idea for Brokia: standardize ingestion to DoclingDocument JSON, then build policy/quote “field packs” (coverage, exclusions, limits) as extractors over that schema.

2) Docling’s MCP server and “agentic” integrations
   - Why it matters: MCP makes document tools callable in a controlled, typed way from agents, which helps governance and observability.
   - Links: https://docling-project.github.io/docling/usage/mcp/
   - Idea for Brokia: run Docling MCP inside the VPC and expose only whitelisted operations (parse, table extract, metadata) with audit logs.

3) Unstructured open-source ETL for partitioning and pre-processing
   - Why it matters: widely adopted partitioning/chunking primitives, useful as a comparative baseline vs Docling for robustness and cost.
   - Links: https://github.com/Unstructured-IO/unstructured , https://docs.unstructured.io/
   - Idea for Brokia: A/B ingestion pipeline (Docling vs Unstructured) on real broker policy PDFs and track extraction accuracy per field.

4) Deepgram positioning: unified Voice Agent API (STT+TTS+orchestration)
   - Why it matters: fewer moving parts can reduce latency and operational complexity for voice-first broker workflows.
   - Links: https://deepgram.com/
   - Idea for Brokia: prototype “voice-to-claim-intake” that collects structured FNOL fields, then hands off to WhatsApp summary.

5) Twilio WhatsApp primitives (Messaging/Conversations/Verify) for broker comms
   - Why it matters: WhatsApp is often the cheapest/highest response channel in LATAM for OTPs and back-and-forth customer flows.
   - Links: https://www.twilio.com/docs/whatsapp
   - Idea for Brokia: implement dual-channel verification (WhatsApp-first, SMS fallback) for insured onboarding and claims status.

6) OWASP GenAI Security Project / LLM Top 10 as shipping checklist
   - Why it matters: gives a concrete taxonomy for the risks that matter in broker copilots (prompt injection, sensitive data exposure, insecure output handling).
   - Links: https://owasp.org/www-project-top-10-for-large-language-model-applications/ , https://genai.owasp.org/llm-top-10/
   - Idea for Brokia: add a “security gates” template to every agent tool (input validation, tool allowlists, redaction, logging, jailbreak tests).

## Ideas accionables para Brokia (3–5)
- Define a gold dataset of 50 real policies/quotes (anonymized) and score Docling vs Unstructured on extraction accuracy for: insurer, coverage, deductible, exclusions.
- Add MCP-based document tooling behind a strict allowlist with per-call audit logs, then measure regression risk vs direct library calls.
- Prototype WhatsApp-first flows (quote follow-up, renewal reminders, FNOL intake) and measure response rate vs email.
- Create an OWASP LLM Top 10 based threat-model checklist for every new “tool” added to the broker copilot.
